Settings row breakpoint

The reviewed settings rows switch to the stacked layout when the settings pane is narrower than the breakpoint. This page previews the calibration that replaced the 660px rule: rows now stack below 400px of pane width, so a tablet-sized pane keeps the two-column layout and only a phone-sized pane stacks. Every pane below uses a live container query; nothing is simulated by device flags.

Before — stacks below a 660px pane

A 526px pane (an 800px settings window) still stacked, which is the report in issue #1819: dropdowns and buttons spanned the pane on a tablet-sized window.

After — stacks below a 400px pane

The tablet-sized pane keeps the label beside its control, and only the phone-sized pane stacks. Switches stay beside their label at every width.

Transition: the two-column layout holds until the pane drops below 400px, which is a settings window of roughly 665 CSS px (≈1330 device px on a 2× display — where core's own settings switch was measured).

Pane width by settings window

Measured in Obsidian 1.15.1 with the plugin build from this branch: the pane is core's setting-group column, so it saturates at 688px.
