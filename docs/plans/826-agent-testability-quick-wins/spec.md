## Objective

Plugin state and controls can be read and operated through user-facing semantics (roles, names, states, palette commands, live announcements) so that automated and AI-driven tests need fewer round trips, and keyboard and screen-reader users get the same access. Human access is the purpose; agent speed is the benefit. This is not a WCAG conformance claim.

Observable outcome: a tester can read the running build, reach every Reader/dashboard/settings action from the command palette or keyboard, and wait on a readiness signal, without pixel clicking or fixed timeouts.
