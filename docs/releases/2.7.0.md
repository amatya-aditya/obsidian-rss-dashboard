# RSS Dashboard 2.7.0

RSS Dashboard 2.7.0 brings your starred articles over from other feed readers, makes your data safer and easier to find, and gives you more control over which kinds of articles are protected from automatic cleanup. It also adds an image lightbox, a redesigned podcast episode list, new grouping options, and a What's New summary after each update.

---

## Import your starred articles

- Import starred articles from a Google Reader-compatible `starred.json` export, confirmed with Inoreader and FreshRSS. Start from the command palette, the Manage Feeds sidebar icon, or **Settings → Import/Export**.
- Preview the import before making any changes. Articles are grouped by source feed. You choose exactly what to import, and anything that can't be imported is listed with a reason.
- Feeds you don't already follow are created automatically in a folder of your choice (**Starred imports** by default).
- Labels from the export become tags. You can adjust each article's tags in the preview, and any new tags that would be added to your palette are shown before you import.
- Re-running the import updates previously imported articles instead of creating duplicates.
- Imported articles initially use the summary included in the export. Use **Fetch now** in the reader whenever you want RSS Dashboard to retrieve the full article text.

See the [Import Starred Articles Guide](../starred-import-guide.md) for details.

## Safer storage

- Fixed a Shard storage v2 issue that could lose read, starred, tagged, saved, and playback state when a feed had not loaded or synced yet—and could then spread that loss to other devices through sync.
- Shard storage v2 now safely removes stored article state after an article has been gone from its feed for 90 days, without touching feeds that have not loaded successfully.
- Deleting a feed now also removes its shard file. Missing or corrupted shard files are flagged in the sidebar and rebuilt automatically when possible.
- Fixed reverting to Legacy JSON loading an empty dashboard, and prevented an unreadable settings file from resetting your configuration to defaults.
- Backups now reliably create a recovery snapshot when data backup is enabled.
- **Settings → Storage** now shows where your data is actually stored and points out any leftover `user-state.json` from an earlier setup.
- With Shard storage v2, **Settings → Storage** now warns when your read, starred, and tag state (`user-state.json`) is in a hidden folder that won't sync.
- Settings that sync in from another device now take effect right away instead of after restarting Obsidian.
- Export and import your feeds and your app settings separately with the new **Feed bundle** and **Settings bundle**.

## Storage modes are being retired

Legacy JSON and Shard storage v1 are now deprecated and will become read-only in 3.0. Once that happens, feeds will no longer refresh and changes to read state, stars, tags, and saved articles will no longer be recorded.

The migration reminder can be skipped for one release at a time, but can no longer be permanently dismissed. If you still use either mode, switch to Shard storage v2 from **Settings → Storage** before upgrading to 3.0.

## Control what retention keeps

- Choose whether starred, saved, tagged, and unread articles are protected from automatic expiration and item-limit cleanup. Existing users keep starred and saved articles protected.
- Unread articles older than a feed's auto-delete cutoff are now removed unless you choose to protect them.
- Articles with no publish date now show **Unknown date** instead of **Invalid Date**. Turn on **Use first-seen date for undated items** to sort and retain them using the date RSS Dashboard first saw them.

## Reading, listening, and organizing

- Tap or click an image in the reader to open it full size with zoom and pan.
- Browse podcast episodes in a simpler list that loads more on demand, with cleaner playback controls on mobile.
- Group articles by **Date > Feed** or **Folder > Feed**.
- Move multiple selected feeds and folders at once with **Move selection to folder**.
- Delete a feed from the Edit feed window, or clear all feeds and folders from the 'Manage Feeds' sidebar icon.
- Saved-note templates now support `{{saveDate}}`, `{{saveTime12}}`, `{{saveTime24}}`, and `{{firstSeen}}`.
- A short **What's New** summary now appears once after each update and can be reopened from **Settings → About**.
- **Settings → About** now shows the exact build you're running, with a copy button for bug reports.
- AI Weekly has been added to the Discover catalog.

## Notable fixes

- Automatic refresh no longer causes repeated notifications, list flashes, or scroll jumps. Each feed's refresh indicator now clears as soon as that feed finishes, and the **Stop** button is available on mobile.
- Starring an article no longer adds or removes a **Favorite** tag. Stars and tags now work independently.
- Adding a Discover feed to **Root (no folder)** or a newly created folder now puts it exactly where you selected.
- Selecting multiple sidebar feeds now applies drag, move, and delete actions to the full selection instead of acting on only one feed.
- The **Delete selection** confirmation now counts everything the delete removes, including feeds inside selected folders.
- Dashboard keyboard shortcuts now keep working after **Move to new window**, and pause while a dialog is open so a quick keypress can't act on something you're no longer looking at.
- Renaming or recoloring a tag now updates every article card that carries it.
- Code blocks in the reader now wrap within the reader instead of running off the edge.
- Fixed saved-note frontmatter breaking when article titles or other fields contain quotes.
- Fixed several RSS2JSON fallback issues, including incorrect dates and languages, malformed feed data, and articles overwriting each other's state.

## Removed

Nitter support and automatic X/Twitter feed conversion are removed following Nitter's shutdown. Adding an X or Twitter URL now explains this and suggests an RSS bridge instead.

## Compatibility and maintenance

RSS Dashboard now requires Obsidian 1.8.7 or later. This release also includes maintenance work to improve release validation and resolve the remaining Community Plugin scorecard findings.

The full list of changes is in the [changelog](../../CHANGELOG.md).
