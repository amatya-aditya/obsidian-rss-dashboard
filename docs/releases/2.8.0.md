# RSS Dashboard 2.8.0

RSS Dashboard 2.8.0 makes reading faster, improves control over how articles are saved to your vault, and strengthens reliability across large feed libraries and synced devices. Read RSS content immediately while full articles load in the background, customize saving behavior for individual feeds, navigate timestamped podcast chapters, and enjoy faster startup, more responsive article interactions, improved accessibility, and expanded media support.

---

## Faster reading and performance

- **Read while articles load.** The Reader and inline reader show RSS content immediately while the full article is fetched in the background. Switch between RSS and fetched content whenever you need, with a separate reading position for each version. Failed fetches are remembered rather than repeatedly attempted on every open, and you can retry when you're ready.
- **Much faster startup.** Redundant file reads, article copying, and repeated settings upgrades have been eliminated from key startup paths. In a test vault with 205 feeds, measured plugin load time fell from approximately 3.2–3.3 seconds to 1.5–1.8 seconds.
- **Instant article-state updates.** Marking articles read or unread now updates the list, sidebar unread count, and filter counts immediately, without waiting for the save to finish. Stars, tags, saved-note associations, and playback progress also use a more efficient persistence path.
- **More durable article state.** With Shard storage v2, a new device-local journal records article-state changes immediately, while shared-state checkpointing happens in the background. Recent changes can survive an abrupt Obsidian close or a synced settings reload without being lost.

## Save articles your way

- **Flexible saved-note templates.** Edit templates independently, choose a global default, assign different templates to individual feeds, and configure custom folders and filename patterns. Filenames are handled safely to avoid collisions while preserving identified note paths.
- **Choose which content to save.** The new **Default save version** setting lets you choose between RSS content and fetched article content. Individual templates can override that choice, so different feeds can use different versions without changing your global preference.
- **More control over each save.** Dashboard save actions now offer **Save with default settings** and **Save to custom folder...**, matching the Reader. Choose the destination and filename pattern for an individual save.
- **More informative saved notes.** The new `{{contentSource}}` template variable records whether a note contains RSS content or fetched content. Saved notes also preserve HTML tables as Markdown tables and use the same cleaned fetched article body displayed in the readers.

The built-in default template includes `{{contentSource}}`. If you've already customized and saved your own default template, add `contentSource: "{{contentSource}}"` manually or reset the default template under **Settings → Article Saving** to include it.

## Reading, listening, and media

- **Fetch and restore article covers.** Fetch an article's declared cover image from its webpage, replace an existing cover, or restore the image provided by the feed. The fetched image is used consistently across the card, feed view, Reader, and saved-note image template. Fetching a cover does not mark the article as read or save its full content.
- **Podcast chapter markers.** Episodes with timestamped chapters in their descriptions now show clickable markers on the seek bar. Hover or focus a marker to preview the chapter's title, start time, and length, or select it to jump directly to that chapter. Markers can be enabled or disabled under **Settings → Media → Podcast player**. Episodes without chapter timestamps will not show markers.
- **Preview the sleep timer.** A second progress band shows how far playback is expected to advance before the sleep timer stops it. The preview accounts for playback speed and responds immediately when you seek or change speed. Both the chapter markers and sleep-timer preview are enabled by default and can be turned off in settings.
- **Expanded video playback.** Twitch VODs now play in the Reader and inline reader. YouTube videos embedded in feed content can play inline on demand, and saving a YouTube video item now produces a playable embed with a **Watch on YouTube** link.
- **A cleaner YouTube experience.** The YouTube player's optional Focus mode hides surrounding article details so you can concentrate on the video. Enable it under **Settings → Media → YouTube player** or toggle it using the command palette.

## Accessibility and dashboard usability

- **Better keyboard navigation and screen-reader support.** Dashboard and Reader controls are easier to reach and operate using the keyboard. Focus is handled more consistently when menus open, articles leave a filtered list, or settings tabs change. Screen readers receive clearer announcements for refresh activity and interface controls.
- **Respect for reduced motion.** RSS Dashboard now honors the operating system's reduce-motion setting, reducing decorative transitions and animations while keeping useful loading indicators visible.
- **Rename tags in one place.** The Tags settings tab now lets you rename a tag directly. The new name propagates to article tags, folder auto-tag rules, per-feed custom tags, and Auto tagging defaults so the tag continues to work throughout your setup.
- **Clearer keyboard shortcuts.** The shortcut reference groups actions by where they work, and dashboard controls identify their corresponding shortcuts. You can also return the article list to the start of the current view without losing your filters or search.
- **More consistent navigation.** Discover filters are easier to select, folder controls have larger touch targets, and search queries remain intact when the dashboard redraws, changes pages, refreshes, or switches views.

## Notable fixes

- **More reliable feed parsing.** Feeds that use namespace-prefixed RSS or Atom elements now import correctly, and relative article links resolve against the feed's declared website when appropriate.
- **Better article titles and formatting.** Article and feed titles no longer display literal escaped HTML tags. Fetched pages handle more image formats and publisher markup correctly, reducing missing images and unwanted interface text appearing in article content.
- **Saved content matches the Reader.** Notes saved from fetched articles now use the same cleaned body displayed in the readers, avoiding repeated introductions, navigation elements, and duplicated lead media.
- **More reliable syncing.** Changes to feeds, folders, settings, and article state are less likely to overwrite unrelated changes arriving from another device. Shard storage v2 also handles incoming shard changes more reliably.
- **Clearer feed and proxy errors.** Failed background feed imports now report their failures rather than failing silently. Proxy settings include options to test all proxies or a selected proxy, with results showing which connections are fast, slow, timed out, or failed.
- **Safer interactions.** Destructive settings actions request confirmation, mobile cover controls are easier to tap without accidentally opening an article, and several keyboard-focus and interface-state issues have been corrected.

## Known issues

If you store the metadata `data.json` in a vault folder using **Settings → Storage → Metadata data.json location**, an import of a Portable data bundle, Feed bundle, or Settings bundle can be lost if Obsidian closes before another change is saved. After importing, change a setting or mark an article as read before closing Obsidian. The default metadata location in the plugin folder is not affected. [GH Issue #474](https://github.com/amatya-aditya/obsidian-rss-dashboard/issues/474)
